**Merged 2026-11-15/16, each through both reviews (`/code-review high` + a Sonnet reviewer) and the two-phase gate:**
- B615; B745 (a POV recorder's observer camera is `CalcObserverView`, `ObserverCamera`); B738 (freeze frame take and
  hold, `FreezeFrame`); B739 (a NextBot gathers no IK rule).
- B747: the SourceTV chase and in-eye cameras read their target and the players their trace meets as DRAWN. Paused, the
  drawn players are the HELD ones: `SpectatorView.Interpolating` carries the window's `Playing`, and
  `IEyeSource.PlayersAt(double, into, interpolating)` passes it on.
- B749: a player's eye angles interpolate. **His pose's `Pitch`/`Yaw` already ARE `m_angEyeAngles`** (`RecordProp`:
  his `m_angRotation` is not networked), so the simulation history always slerped them; the rebuild had dropped the
  result. The first fix added a duplicate history, and both reviews caught it.
- B750: every player's feet turn once a FRAME (`PlayerFeet`, formerly `RecorderFeet`). The rules are the engine's:
  - the frame time is the frame's, not the player's own gap;
  - a second ask within one frame reads without turning;
  - a backward move restarts everyone.

  The real-match assertion is `CorpusOtherPlayersFeetTests` (lcor).
- B748: the freeze panel (`Scene/Hud/TfFreezePanel.cs`). show/hide_freezepanel and freezecam_started are CLIENT
  events, derived from the observer mode (`FreezeEvents`). "Nemesis" reads `m_bPlayerDominatingMe`, which only the
  recorder's slot carries (`ScenePlayer.IsDominatedBy`). Seen on screen at etf2l-12025 tick 2090; not compared with TF2.
- B753: a `--shot` during the freeze hold hung 30 minutes. The hold draws no world, so the capture must not wait on
  post-processing or glows (`IRenderDevice.ShowingFreezeFrame`).
- B744: a paused viewer re-poses the held moment every render frame at the HUD's real time
  (`MomentPresenter.NextFrame`), because `OnRenderStart` invalidates bones each frame and jiggle steps on realtime. A
  re-pose is not a rebuild and walks no animation event.

**What the reviews kept finding, worth checking before committing:**
- a paused frame is a different sample from a playing one (`Held`, no `cl_interp` delay);
- several consumers sample players in one frame, so per-frame state must be idempotent within a frame;
- a value the codebase already computes elsewhere (read `RecordProp` before adding state);
- a test whose control passes for the wrong reason, such as a first keyframe answering early;
- a client-side event needs the preconditions the engine checks before firing it (freezecam_started needs a target).

**Tool trap:** agent-lsp `rename_symbol` applied STALE offsets to a file edited after the LSP opened it. It wrote
"Play" into seven wrong places in `DemoTimeline.cs` and missed the real references. Before trusting a rename, check
`git diff`; repair with exact inverse edits.
