**What the reviews kept finding, worth checking before committing:**
- a paused frame is a different sample from a playing one (`Held`, no `cl_interp` delay);
- several consumers sample players in one frame, so per-frame state must be idempotent within a frame;
- a value the codebase already computes elsewhere (read `RecordProp` before adding state);
- a test whose control passes for the wrong reason, such as a first keyframe answering early;
- a client-side event needs the preconditions the engine checks before firing it (freezecam_started needs a target).

"Play" into seven wrong places in `DemoTimeline.cs` and missed the real references. Before trusting a rename, check
`git diff`; repair with exact inverse edits.
