Owner, correcting the assistant twice in one exchange: *"even running the period client doesnt
actually date the demo, i dont know why you think it does"*.

**A period client dates a protocol.** A build of known date reports a `version`, which establishes
that protocol N was current then. **A demo dates nothing by itself** — one speaking protocol 22 was
recorded somewhere inside protocol 22's lifetime and inherits that window.

Three separate questions, routinely blurred into one:

| Question | Answered by |
|---|---|
| Do we hold a file speaking protocol N? | a **specimen** |
| When was protocol N current? | a period **client** |
| When was THIS demo recorded? | its own evidence — filename, map version, seasonal content |

**Why it matters:** the four recovered protocol 21/22 demos close the specimen gap and cannot touch
the dating gap, so "we have 21 and 22 now" must not become "21 and 22 are dated". The related error
was making a test's protocol allow-list wait on dating — the container test asks a question about
file contents, and coupling it to history would have left known-good demos red for ever, since a
scrim has no league record to date it from.

**How to apply:** say which of the three questions is being answered before claiming a gap closed.
