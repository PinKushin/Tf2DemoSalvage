# B612's open items: beam allocation, attribute walk cost, top-bar shots (2026-11-15)

## Observation

B612 (`docs/RISKS.md`) carried three unmeasured reports from the 2026-10-29 allocation branch: a beam that "still
allocates 176 bytes a frame, location unknown"; the attribute walk's O(local × fallback) scan, "time one before it
matters"; and a top-bar difference between paused empty-view shots of one build ("the dark background present or
absent, run to run", `2026-10-29-econ-attribute-walk.md`, Identity).

## Question

1. Does a beam's build still allocate?
2. What does one attribute walk cost at realistic and large list sizes?
3. Does the empty view's top bar differ between paused shots of one build?

## Method

1. `EffectEntitiesTests.BuildOver_ABeamFrameBuiltAgain_AllocatesNothing`: the spotlight frame built once, then again
   between two `GC.GetAllocatedBytesForCurrentThread` reads.
2. Probe `attribute-walk` (`tools/Tf2DemoSalvage.Probe/Probes/AttributeWalkProbe.cs`), Release: `EconAttributes.Iterate`
   walked 200,000 times at 5, 10, 20, 40 and 80 entries per list, half the fallback definitions present locally.
3. f12 (`D:/measure-f12/f12.dem`), `--tick 30000 --shot`, `TF2VIEW_CAMERA="1613 -2821 154 89 0"` (the empty view), Debug
   build of `5eb886610`, under `run-exclusive.ps1`. First 4 shots at the default 984x551; then 6 at
   `TF2VIEW_VIEWPORT_SIZE=1280x720`, with a 3-second `--measure` run before shots 2, 4 and 6, the order the original
   queue interleaved. Compared pixel by pixel (every second column), whole frame and the top 49 rows.

## Control

1. The same build draws the beam (`Corners` non-empty, asserted); an `object[20]` allocated at the top of `BuildOver`
   turns the test red.
2. The count walked equals local + fallback / 2 at every size.
3. The top-49-row count is a subset of the whole-frame count; a differing frame anywhere would show in the whole count.

## Environment

Desktop, i7 6 physical cores, other agents idle; commit `5eb886610` plus the uncommitted test and probe. Load not sampled
(no timing is claimed from the shots; the probe's numbers are a per-walk mean, run once).

## Result

1. Beam: 0 bytes, beam drawn. The control run with the injected array failed, as it must.
2. Probe output, two runs, verbatim. The first version warmed with one walk, and its 5-per-list figure (154 ns, slower
   than 10 per list) was tier-0 JIT; the probe now warms each size for as many walks as it times, and fails when the
   control does not hold.

   ```
   5 local x 5 fallback: 32.7 ns a walk, 7 walked (control: 7), sum 1400000
   10 local x 10 fallback: 136.4 ns a walk, 15 walked (control: 15), sum 3000000
   20 local x 20 fallback: 589.1 ns a walk, 30 walked (control: 30), sum 6000000
   40 local x 40 fallback: 1620.5 ns a walk, 60 walked (control: 60), sum 12000000
   80 local x 80 fallback: 6409.3 ns a walk, 120 walked (control: 120), sum 24000000
   5 local x 5 fallback: 32.2 ns a walk, 7 walked (control: 7), sum 1400000
   10 local x 10 fallback: 141.6 ns a walk, 15 walked (control: 15), sum 3000000
   20 local x 20 fallback: 420.2 ns a walk, 30 walked (control: 30), sum 6000000
   40 local x 40 fallback: 1586.0 ns a walk, 60 walked (control: 60), sum 12000000
   80 local x 80 fallback: 6287.9 ns a walk, 120 walked (control: 120), sum 24000000
   ```

3. Shots: 984x551, shot 1 against 2, 3, 4: 0 differing pixels whole and top. 1280x720, shot 1 against 2-6: 0 whole, 0 top.

## Verdict

1. Not reproduced: no beam code changed, and the spotlight fixture allocates nothing. Which beam gave the 10-29 bytes was
   never recorded, so whether an earlier B599 commit removed them or this fixture never reached them is not known. The
   new test holds the spotlight's build at 0.
2. A walk is 0.03-0.14 µs at TF2's usual item sizes (5-10 per list) and grows as local × fallback, which is the engine's own linear
   `GetAttributeByID` (`econ_item_view.cpp:560-562`); nothing changes. How many walks a real frame makes is not measured.
3. Not reproduced in ten shots. The 10-29 difference came from Release builds made by `git archive` and has not recurred
   on this tree; the item is closed as not reproduced, with this method to rerun if it is seen again.
