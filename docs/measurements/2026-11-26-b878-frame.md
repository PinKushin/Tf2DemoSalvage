# B878 frame cost against main (2026-11-26)

## Observation

B878 makes every sampled server-animated prop ask its track for an unseen reset (`ScenePropTrack.UnseenResetAt`, through
`CycleAnchor`) in both `At` and `Motion`, and a prop never set up — a culled one, parity −1 — anchors on every update, so
`InterpolatedHistory.BracketAnchored` builds and walks its list on each sample (Fable, B878 review 11, read from the
code). The presenter also walks the posed set every frame (`NoteBonesSetUp`), outside the `sample` phase. On f12 at
tick 20000 about 1,350 of 1,850 selected props are hidden by the PVS (the viewer's own `posed … hidden by pvs` line),
so most props are never set up. A first, single run each (review 10) could not resolve a difference and picked
intervals inconsistently (reviews 11, Codex, Fable, Sonnet, the cavecrew reviewer); its numbers are withdrawn.

## Question

Does B878 change the viewer's frame time or its moment cost on f12, by more than 0.05 ms a frame?

## Method

`TF2VIEW_AUTOPLAY=1 pwsh run-exclusive.ps1 tf2demoview <f12> --tick 20000 --first-person --measure 20 +fps_max 0`,
f12 = `demostf-cp_process_f12-2026-08-08-2207`. Debug builds of each commit, six runs alternating main, branch, main,
branch, main, branch, so drift and order fall on both alike. Per run, the mean over every rate interval AFTER the first
(the first holds the opening stalls) of: the frame ms, the moment cost ms and its `sample` ms. Per build, the mean and
the range of its three run means; the difference is the branch's mean less main's, against the larger of the two
builds' run-to-run ranges.

## Control

Each run's `measured … seconds of playback` line, and its count of rate intervals: a run cut short, or one that played
fewer ticks, is not comparable and is dropped and said so. The run-to-run range of each build is the instrument's own
noise: a difference inside it is not resolved.

## Prediction

No difference above the noise in frame ms or moment cost; the `sample` phase up by at most 0.05 ms on the branch.
Falsified if the branch's mean exceeds main's by more than the larger run-to-run range in any of the three.

## Environment

Machine load before and after: read with the lock held, recorded per run below. Commits: main `dbe8b702c` (detached
worktree), branch `fix/b878-predraw-cycle-reset` at the commit that adds this file (Core code as at `363d0ef1d`).

## Verdict

**Prediction confirmed.** Frame time and moment cost show no difference above their noise (+0.07 ms against a 0.80 ms
range; +0.078 against 0.277). The `sample` phase rises by 0.034 ms a frame, 0.4% of an 8.2 ms frame: inside the
predicted 0.05 ms and inside the larger range, but every branch run (0.253-0.294) is above every main run (0.238-0.241),
so the rise is consistent rather than noise — the cost of B878's per-sample unseen-reset query and anchored walk on a
scene where most props are never set up. It is a parity fix, so the cost is kept (D89); a cheaper walk, if wanted, is
separate work against this file's numbers.
