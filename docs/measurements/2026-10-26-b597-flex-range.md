# Measurement 2026-10-26: sending only a face's flexed range against the whole stream (B597)

## Record (written and committed before the first run)

## Observation

`2026-10-26-b597-face-cache.md`: on f12 gummo first person, mode 2, 1280x720, about 5.4 faces are uploaded each frame,
each as its model's whole stream: 3.13-3.15 MB a frame, with the flex span at 0.270-0.277 ms.
`2026-10-26-b597-flex-extent.md`: a class face's first-to-last flexed span is 25-55% of its buffer (f12's classes:
scout 34.5%, soldier 44.6%, demo 49.9%, medic 39.0%).

## Question

What does uploading only each face's flexed range — a zero-initialised DEFAULT buffer per model plus `UpdateSubresource`
over that range (branch `perf/b597-flex-upload`) — take off the flex span's bytes and CPU, OpaqueModels, the render
thread's draw and the frame?

## Prediction (before the runs)

- **Bytes:** 3.15 MB a frame falls to 1.2-1.6 MB. *Arithmetic:* f12's four classes span 34.5-49.9%, weighted by which
  faces are on screen.
- **Flex CPU:** 0.27 ms falls to 0.10-0.18 ms, if the cost is the copy. `UpdateSubresource` on a buffer the GPU may still
  be reading can make the driver copy twice (into its own staging, then to the GPU). If it does, the saving shrinks
  toward nothing, and that is the risk this run measures.
- **OpaqueModels:** falls by the same amount as the flex span. **Render thread draw:** falls by about the same, near its
  spread. **Frame:** unchanged within its spread.

Falsified per line if the measured value is outside the stated range beyond the run-to-run spread.

## Instrument

`--measure`'s pass ledger and `SubmitSpans` (`c0584951`). The `Flex` span's laps are every model draw, and its bytes are
what was copied. M's bytes are whole streams; R's are the ranges, read where the copy is issued (B243). Driver worker
CPU comes from finding 100's thread sampler.

## Method

Release builds, `MSBUILDDISABLENODEREUSE=1`, 0 warnings:
- **M** = `c0584951` at `D:/b597f/M`, the same binary as the face-cache grid: the whole stream every draw, one shared
  buffer.
- **R** = this branch's head, exported to `D:/b597f/R`: the flexed range.

Each run is one viewer, run exclusive, through `2026-10-25-render-thread-cpu-vs-gpu/run.ps1`. That script supplies the
quiet gate (no build or test process; three load samples under 25%) and the command (f12 tick 30000, gummo first person,
1280x720, `--measure 20 +fps_max 0 +mat_queue_mode 2`).

**Order: M R R M R M M R** (ABBA, then its reverse; four of each). A run whose before or after load has any sample of
25% or more is discarded and repeated at the end, in the same condition. Every run's loads are listed. Raw stdout and
sampler CSVs go in `2026-10-26-b597-flex-range/`.

## Identity (output parity must be exact)

- `FaceFlexRenderTests.Draw_FacesThroughTheirFlexedRange_IsPixelIdenticalToSendingTheWholeStream`: four frames of one
  model (moved, moved another way, at rest, moved again), ranged against whole, every pixel equal. Its control: a delta
  outside the range is dropped through the range and shows when sent whole.
- `FaceFlexDemoRenderTests.Render_ASoldierLaughing_DrawsADifferentFaceFromTheSameBonesWithoutIt`: the real laughing
  soldier from four sides, sent through its range against the whole stream, identical.
- `FaceFlexAnimationDemoTests.FlexRange_AMedicPlayingAFlexAnimation_HoldsEverySlotThatMoves`: the scene's half. Every
  moving slot of every frame lies inside the range, and the range is the model's first to last flexed slot.
- **Sabotage:** sending one slot fewer reddened the four-frame A/B. A range one slot short reddened the medic test.
  Sending half the range reddened the A/B and the soldier test.
- One extra R run, untimed, with `TF2VIEW_QUEUE_VERIFY=1`, must read 0 changed. The verifier has no positive control
  (measurements/2026-10-25-b599-three-allocation-sites.md proposes one). It also cannot see a range that is too short,
  because the floats match at hand-off and after the draw. The tests above are the guard for that.

## Control

(a) OpaqueModels draws are 209 in both conditions. (b) The `Flex` span's laps are equal in M and R (one lap per model
draw). (c) Every run is 1280x720 with 0 skipped.
